# Performance baseline: 2026-08-08

This is the first RazorLight 3.0 observation baseline. Both revisions were built from source and run
back-to-back with BenchmarkDotNet 0.15.8 on Windows 11, .NET SDK 10.0.204/.NET 10.0.8, and an Intel
Core Ultra 9 275HX. The `ShortRun` job uses one launch, three warmups, and three measured iterations.
Its confidence intervals are intentionally broad, so small differences are noise rather than claims.

The comparison uses `45b0c73` (immediately before TASK-034) and `b5f1f12` (after TASK-034 through
TASK-038 and TASK-022). Values are means; allocations are managed bytes per operation.

| Scenario | Before time | After time | Before allocation | After allocation | Observation |
| --- | ---: | ---: | ---: | ---: | --- |
| Cold string compile | 97.25 ms | 86.94 ms | 6.89 MB | 6.92 MB | 10.6% faster; allocation effectively flat |
| Cold file compile | 79.41 ms | 76.33 ms | 6.91 MB | 6.93 MB | Difference within ShortRun noise |
| Cold embedded compile | 79.80 ms | 70.87 ms | 6.95 MB | 6.97 MB | 11.2% faster; allocation effectively flat |
| Large string compile | 137.37 ms | 131.49 ms | 14.38 MB | 14.65 MB | Difference within ShortRun noise |
| Same-key cold concurrency | 98.22 ms | 102.20 ms | 6.93 MB | 6.95 MB | Difference within ShortRun noise; tests prove single flight |
| Unrelated-key cold concurrency | 325.39 ms | 281.90 ms | 14.25 MB | 14.38 MB | 13.4% faster; allocation effectively flat |
| Cached render | 1.079 us | 1.068 us | 2.53 KB | 2.32 KB | Time flat; allocation reduced 8.3% |
| Cached render with DI | 9.556 us | 1.577 us | 7.19 KB | 2.45 KB | 83.5% faster and 65.9% less allocation |
| Layout and three includes | 3.854 us | 4.041 us | 8.48 KB | 7.51 KB | Time within noise; allocation reduced 11.4% |
| Engine construction/disposal | 35.417 us | 21.547 us | 41.78 KB | 47.91 KB | 39.2% faster; lifecycle tracking adds allocation |
| Deterministic disk-cache load | 3.214 ms | 4.214 ms | 108.9 KB | 402.44 KB | Strong dependency/version fingerprinting costs more than the old unsafe single-file MD5 lookup |

The strongest supported improvement is cached dependency injection, where TASK-037 removed repeated
property discovery. Independent compilation and construction also improved materially in this run.
TASK-036 is a correctness and determinism tradeoff, not a speed win: streaming removes the old
whole-file concatenation peak, while hashing all relevant dependencies and compiler inputs performs
more total work. No timing budget is set from this single baseline; the versioned coverage floors are
the only automated numeric ratchet at this stage.
